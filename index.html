Groups and shared brains

Link your projects, and every conversation about them counts

On its own, Claude Code knows one folder at a time. A thread in your app project can't see the thread where you settled the API, and neither can see the claude.ai chat where the client signed off on the design. Each new session starts from that folder's CLAUDE.md.

A group in Ai Project Hub links those pieces. Put a client's projects, its Claude Code threads, its claude.ai chats, its bots, and its files in one group, and they work as one body of knowledge.

  • All the talk in one place. Every Code thread and claude.ai chat in the group shows on one chart, next to its projects, bots, and files. Open any of them and reply from the same window.
  • One brain for the group. A single page with what the group is about, what was decided, how the pieces connect, and what's happening now.
  • Decisions travel. Something agreed in a claude.ai chat or in one project's thread reaches the next message in every other project in the group, because each new message and bot run starts with the brain.
  • It keeps up. A new brain catches up on what the group already holds. After that, a keeper reads new threads, chats, commits, and bot reports each day or week and suggests updates for you to approve.
  • Groups overlap. A project can be in a client group and a team group at the same time.

Two machines, one code base

Work on the same code from your desktop or your laptop

Your projects stay in one place: the folders on your desktop. Your laptop works on those same folders, with the same Claude Code sessions, groups, and brains. There's no second copy of the code to keep in step, no repo to pull first, and no thread that only exists on one machine.

  • Link once. Both screens show the same six digits, and you confirm they match. After that, the laptop connects whenever both are on.
  • Everything, live. The laptop shows the desktop's projects, threads, groups, bots, and runs as they happen.
  • Runs where the code is. When you reply from the laptop, Claude Code works on the desktop, in the real project folders, with the group's brain.
  • Private. Messages between your PCs are encrypted end to end. Our server passes them along and can't read them.
  • Included in Pro. 2 devices: your main PC and a remote one.

Bots you can see

Build a bot by filling in a flow, not a config file

Each bot does one job, like reviewing new commits, checking that docs are current, or researching a topic each week. It's drawn as six steps: when it runs, where, its job, its rules, what it may use, and where the results go. Click a step to change it. The sentence at the top always says what the bot will do.

  • Start from a template, or describe the bot in a sentence.
  • Test run it and watch each step before it runs on its own.
  • Run it on a schedule, after each commit, or by hand. Schedules keep running with the app closed.
  • Bots can only read unless you allow more. They never commit, push, deploy, or publish.
